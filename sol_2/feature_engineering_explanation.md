# 特征工程说明与验证方法

## 一、特征工程说明

本项目中实现了7个特征工程特征，每个特征都有其业务意义和数学原理：

### 1. 可负担性比率 (Affordability Ratio)
- **公式**: `customer_salary / (price + 1)`
- **原因**: 
  - 单独看工资或房价无法判断客户是否负担得起
  - 比率更能反映真实购买能力
  - 高比率 = 工资相对房价较高 = 更容易负担 = 更可能购买
- **业务价值**: 将两个相关但不同量级的特征转化为有意义的业务指标

### 2. 贷款价值比 (Loan-to-Value Ratio, LTV)
- **公式**: `loan_amount / (price + 1)`
- **原因**:
  - LTV是金融风险评估的关键指标，反映贷款风险
  - 高LTV = 贷款金额占房价比例高 = 风险高 = 可能影响购买决策
- **业务价值**: 帮助模型理解金融风险对购买行为的影响

### 3. 房产年龄 (Property Age)
- **公式**: `2025 - constructed_year`
- **原因**:
  - 房产年龄比建造年份更直观，直接影响房产价值和维护成本
  - 新房通常更受欢迎，老房可能需要更多维护，影响购买意愿
- **业务价值**: 将绝对年份转换为相对年龄，使特征更有意义且易于模型学习

### 4. 支付能力 (Payment Capacity)
- **公式**: `customer_salary - monthly_expenses`
- **原因**:
  - 月收入减去月支出得到实际可支配收入，这是决定购买能力的关键
  - 高工资但高支出的人可能不如中等工资但低支出的人有购买能力
- **业务价值**: 捕捉收入和支出的综合影响，比单独使用更有效

### 5. 首付比率 (Down Payment Ratio)
- **公式**: `down_payment / (price + 1)`
- **原因**:
  - 首付比例反映客户的财务准备程度和购买诚意
  - 高首付比例 = 客户财务准备充分 = 购买意愿强 = 更可能成交
- **业务价值**: 将首付金额标准化为相对比例，消除房价绝对值的影响

### 6. 风险评分 (Risk Score)
- **公式**: `crime_cases_reported + legal_cases_on_property`
- **原因**:
  - 犯罪案件和法律案件都是风险指标，但单独使用可能不够
  - 组合使用可以捕捉整体风险水平，高风险的房产通常吸引力较低
- **业务价值**: 通过聚合相关风险指标，提供更全面的风险评估

### 7. 质量评分 (Quality Score)
- **公式**: `satisfaction_score + neighbourhood_rating + connectivity_score`
- **原因**:
  - 满意度、社区评级和连通性都是房产质量的指标
  - 组合这些指标可以形成综合质量评分，高质量房产通常更受欢迎
- **业务价值**: 通过聚合多个质量维度，提供更全面的质量评估

## 二、特征工程验证方法

### 方法1: 使用命令行参数运行验证

```bash
# 在 sol_2 目录下运行
python house_predict_pytorch_my.py --validate-fe
# 或使用简写
python house_predict_pytorch_my.py -vfe
```

### 方法2: 修改代码中的标志

在 `house_predict_pytorch_my.py` 文件的 `if __name__ == '__main__':` 部分，找到：

```python
RUN_FEATURE_ENGINEERING_VALIDATION = False
```

将其改为：

```python
RUN_FEATURE_ENGINEERING_VALIDATION = True
```

然后正常运行脚本：

```bash
python house_predict_pytorch_my.py
```

## 三、验证功能说明

验证功能会执行以下操作：

1. **实验1**: 使用特征工程训练模型
   - 应用所有7个特征工程特征
   - 训练模型并评估性能

2. **实验2**: 不使用特征工程训练模型
   - 仅使用原始特征
   - 使用相同的模型架构和超参数训练

3. **对比分析**: 
   - 计算性能提升（准确率、Macro-F1、损失）
   - 生成对比可视化图表

4. **输出结果**:
   - 控制台输出详细的对比结果
   - 生成 `feature_engineering_comparison.png` 图表文件
   - 图表包含：
     - 性能指标对比柱状图
     - 性能提升百分比
     - 训练过程损失曲线对比
     - 训练过程准确率曲线对比

## 四、验证结果解读

验证完成后，你会看到：

1. **特征数量变化**: 显示特征工程增加了多少个特征
2. **准确率提升**: 使用特征工程后准确率的提升（绝对值和百分比）
3. **Macro-F1提升**: 使用特征工程后F1分数的提升
4. **损失降低**: 使用特征工程后损失的降低（损失越低越好）

### 示例输出：

```
【对比分析】特征工程效果提升:
特征数量变化: 20 → 27 (+7 个特征)

准确率提升: 0.8500 → 0.8750 (+0.0250, +2.94%)
Macro-F1提升: 0.8200 → 0.8500 (+0.0300, +3.66%)
损失降低: 0.3500 → 0.3200 (-0.0300, -8.57%)
```

## 五、为什么需要特征工程？

1. **业务理解**: 特征工程将原始数据转化为有业务意义的指标
2. **模型性能**: 好的特征工程可以显著提升模型性能
3. **数据效率**: 通过组合相关特征，模型可以更高效地学习模式
4. **可解释性**: 工程化的特征更容易理解和解释

## 六、注意事项

- 验证过程会训练两个模型，可能需要较长时间
- 验证时使用较少的epochs（50轮）以加快速度
- 正常训练流程使用100轮epochs以获得最佳性能
- 确保有足够的内存和计算资源
